# 训练方法论

> 这份文档回答一个问题：**为什么这套东西能替代"分类 + 总结 + 记忆"？**

---

## 一、为什么"分类 + 总结 + 记忆"会失效

因为你练的是**识别**，不是**生成**。

面试题分类是把题目映射到一个标签（"这是滑动窗口题"），
然后你背下这个标签对应的模板。这条路径的致命缺陷是：

- 它依赖于**题目被正确地贴上了标签**。而真实世界里没人给题目标签。
- 停止刷题后，你失去的不是"知识"，而是**分类器的输入分布**。
  没有新题喂进来，这个映射就慢慢腐烂。

更关键的是：**你从来没有经历过"不知道该用什么"的痛苦状态。**
而算法的真实使用场景，恰恰总是从那种状态开始的。

---

## 二、这套系统换掉了什么

| 旧范式 | 本仓库的范式 |
|---|---|
| 看题解 → 理解 → 记住 | **写暴力解 → 被击穿 → 自己发明优化** |
| 用公式和复杂度证明理解 | 用 **ASCII 内存图 + 爆炸曲线** 理解 |
| 按题型分类 | 按 **`Tier` 规模档位**分类（规模决定算法） |
| 刷完就过 | **间隔重复调度**（`lab due`） |
| 凭感觉判断"会了" | **差分测试**给你客观裁决 |
| 记忆靠重复阅读 | 记忆靠**亲手拆解过爆炸现场** |

核心机制只有一条——**差异化测试（Differential Testing）**：

> 你写的暴力解（正确但慢） vs AI 写的参考解（快）
> 在同一批随机 + 恶意用例上对决。任何不一致，就把那个**具体输入**砸到你脸上。

这条机制之所以有效，是因为它把"我理解了吗"这个无法自证的问题，
转化成"这两份代码为什么给出不同答案"这个**可观测、可调试**的问题。

## 三、每日 90 分钟的标准流程

### 阶段 0 · 看输入（5 分钟）

```bash
cargo run -p lab -- render p0509 --tier tiny
```

**先看 ASCII 图，不要看题解，也不要问 AI。**
你要先在脑子里建立一个"数据长什么样"的物理图像。

### 阶段 1 · 手写暴力解（30 分钟）

打开 `problems/src/pXXXX.rs`，把 `brute()` 从 `todo!()` 改成真的能跑。

- 允许 `O(N³)`，允许难看得要命。
- **不许**想"怎么优化"。这一步唯一的 KPI 是**正确**。
- 卡住了就问 AI —— 但 AI 只会给你反问，不会给你代码。

### 阶段 2 · 被击穿（15 分钟）

```bash
cargo run -p lab -- diff pXXXX --cases 60
```

- 全绿？换种子再来一轮：`--seed 999`、`--seed 12345`。
- 红了？**先别改代码。** 回到失败用例的 ASCII 图，问自己：
  "这个输入里，我的代码第一步走到了哪里？"

### 阶段 3 · 看爆炸（10 分钟）

```bash
cargo run -p lab -- bench pXXXX
```

找到暴力解从"能跑"变成"拒绝运行"的那一行。
**记住那个分水岭规模。** 这个数字比任何复杂度公式都更能留在你脑子里。

### 阶段 4 · 自己发明优化（25 分钟）

现在再回去看阶段 0 的那张图，问自己：

- 哪一步做了**重复**的扫描？
- 如果第一次算完就把结果抄下来，第二次还需要重算吗？
- 指针每移动一步，我丢掉/获得了什么信息？

**你自己想出来的优化，不需要记，因为它本来就是你推理的一部分。**

### 阶段 5 · 记台账（5 分钟）

```bash
cargo run -p lab -- run pXXXX --grade 4
cargo run -p lab -- stats --write
```

`--grade` 要**诚实**。见下一节。

---

## 四、评级是唯一的作弊点，请不要作弊

`--grade` 的分数直接决定**你多久之后会再见到这道题**：

| 分数 | 含义 | 效果 |
|---|---|---|
| 0-2 | 没掌握，靠提示才做出来 | 1 天后重来 |
| 3 | 做出来了但磕磕绊绊 | 1 天后重来 |
| 4 | 独立、顺利解出 | 1 → 3 → 递增 |
| 5 | 能给别人讲清楚 + 通过迁移测试 | 间隔增长最快 |

**虚报高分的代价，是你更晚才见到它——而那时你已经忘了。**
这个系统唯一的约束就是你的诚实。不填则自动：全过 = 4，有不一致 = 1。

---

## 五、数学基础弱怎么办

你不需要数学。你需要的是**把抽象问题变成可数的东西**。

| 你缺的 | 本仓库的替代品 |
|---|---|
| 递推式推导 | `render()` 画出的递归树，`⟲` 标出重复子问题 |
| 复杂度证明 | `lab bench` 的爆炸曲线 + `brute_ops()` 的精确计数 |
| 算法正确性证明 | 差分测试（暴力解就是你的"证明"） |
| 最优性直觉 | 分水岭规模 n（"从 10⁴ 开始崩"比 O(N log N) 好记得多） |

**一个具体数字，胜过十个渐近记号。**

## 六、加一道新题（导入题库）

```bash
cargo run -p lab -- new 49 group_anagrams \
    --title "Group Anagrams / 字母异位词分组" \
    --topic "哈希/排序" \
    --taocp "Vol.3 §6.4"
```

这一条命令做了三件事：生成 `problems/src/p0049_group_anagrams.rs`、
在 `problems/src/lib.rs` 里加 `pub mod`、在 `for_each_problem!` 里注册。
（以前要手动改两个文件共三处，漏一处不会报错，只会在 `lab list` 里静默消失。）

之后 `lab list` / `lab due` / `lab stats` 自动认得它。

**它只生成骨架：`brute()` 里是 `todo!()`。** 这是我唯一不替你做的事。

> ⚠️ 在你写完 `brute()` 之前，`cargo test` 会失败 —— 这是故意的。
> 半成品题目不该被误当成"训练通过"。

如果想让 AI 陪你走一遍开题流程（碰撞边界用例、想清楚输出怎么规范化），
用 `.github/prompts/lab-new.prompt.md`。

想手动来也行：`cp problems/src/_template.rs ...`，然后在 `lib.rs` 注册两行。

## 七、目录地图

| 路径 | 内容 |
|---|---|
| `problems/src/*.rs` | 题目：暴力解 + 最优解 + 恶意用例 + ASCII 渲染 |
| `lab/src/*.rs` | 实验室：差分引擎、爆炸曲线、台账、调度 |
| `records/ledger.tsv` | **训练台账**（append-only，调度状态由它重放推导） |
| `docs/training/stats.md` | 自动生成的统计报告 |
| `docs/notes/*.md` | 你的手写笔记（**自己写，AI 只做格式检查**） |
| `.github/prompts/*.prompt.md` | 四个技能：降维 / 压测 / 复盘 / 新题 |
| `.github/copilot-instructions.md` | 🔴 让 AI 不代写暴力解的约束 |
